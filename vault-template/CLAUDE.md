# CLAUDE.md — このVaultの運用ルール（AI向け）

このVaultは人間（ユーザー）とAI（Claude）が共同で使うナレッジベース。
AIはこのファイルのルールに従って読み書きすること。迷ったら `Home.md` と本ファイルを参照。

## フォルダ構成と役割

| フォルダ | 役割 | 置くもの |
|---|---|---|
| `00_Inbox/` | 未整理の受け皿 | 思いつき、走り書き、とりあえずのメモ。分類不要 |
| `01_Daily/` | 日次ノート | `YYYY-MM-DD.md`。その日の作業ログ・気づき |
| `05_Tasks/` | 単発タスク | 1タスク = 1ノート（`type: task`）。進捗は `タスクボード.base` で一覧 |
| `10_Projects/` | 期限・ゴールのある取り組み | 1プロジェクト = 1フォルダ（`10_Projects/<名前>/_index.md` を必ず置く） |
| `20_Areas/` | 継続的な領域のハブ | `Work/`（仕事）`Learning/`（学習計画・進捗）`Dev/`（開発環境・設定）※必要に応じて増減 |
| `30_Knowledge/` | 恒久的な知識 | 1ノート1トピック。再利用できる概念・手順・Tips・スニペット |
| `40_Resources/` | 外部ソースの要約 | 書籍・記事・動画・講座・公式ドキュメントのメモ |
| `90_Archive/` | 終了・不要になったもの | 完了プロジェクト等。削除せずここへ移動 |
| `99_System/` | 仕組み | `Templates/`（テンプレート）、`Attachments/`（画像等）、`Tags.md`（タグ一覧） |

### 振り分けの判断基準
- 1回の行動で終わる・やることが明確 → `05_Tasks`（タスクノート）
- 終わりがある → `10_Projects`
- 終わりがない・継続的に見る → `20_Areas`
- 他の場面でも再利用できる知識 → `30_Knowledge`
- 他人が作った情報源のまとめ → `40_Resources`（自分の理解・知見は `30_Knowledge` に切り出してリンク）
- 判断できない → `00_Inbox`

## ノートの書式

### ファイル名
- 日本語OK。内容が一目でわかる名前にする（例: `Git rebase の使い方.md`）
- 日付が本質のものだけ `YYYY-MM-DD` を先頭につける（日次ノート、議事録など: `2026-10-02 定例MTG.md`）
- `/ \ : * ? " < > |` は使わない

### Frontmatter（必須）
すべてのノートの先頭に以下を付ける。

```yaml
---
type: knowledge   # daily | project | area | knowledge | resource | memo | meeting | task
tags: []          # 99_System/Tags.md の分類に従う
status: active    # draft | active | done | archived（knowledge は draft/active のみで可。task は下記「タスク管理」参照）
created: 2026-10-02
updated: 2026-10-02
source: ""        # 出典URLや書籍名（あれば）
---
```

- AIがノートを編集したら `updated` を当日に更新する
- AIが新規作成したノートには `author: claude` を追加する（人間が書いたものと区別するため）

### 本文
- 見出しは `#` をタイトル1つ、以降 `##` から
- 冒頭に **1〜3行の要約** を書く（AIが全文を読まずに判断できるように）
- 関連ノートは `[[ノート名]]` でリンクする。末尾に `## 関連` セクションを置く
- 画像等の添付は `99_System/Attachments/`

## AIの作業ルール

1. **探す前に読む**: 書き込む前に `Grep`/`Glob` で既存ノートを検索し、重複があれば新規作成せず追記する
2. **Inbox整理**: 依頼されたら `00_Inbox/` のノートを上記基準で振り分け、frontmatterを整え、関連ノートへリンクを張る
3. **知識の抽出**: 会話や作業で得た再利用可能な知見は `30_Knowledge/` にノート化してよい（作成したことはユーザーに報告する）
4. **日次ログ**: AIが行った作業はその日の `01_Daily/YYYY-MM-DD.md` の `## AIログ` に1行で追記する（ファイルが無ければテンプレートから作成）
5. **削除しない**: ノートの削除はユーザーの明示的な指示がある場合のみ。不要なものは `90_Archive/` へ移動
6. **人間の文章を尊重**: ユーザーが書いた本文は勝手に書き換えない。補足は `> [!note] Claude` のcallout で追記する
7. **テンプレート**: 新規ノートは `99_System/Templates/` のテンプレートを基にする
8. **ハブの更新**: プロジェクトやエリアを追加したら `Home.md` と該当 `_index.md` のリンクも更新する（タスクは `タスクボード.base` に自動で出るのでリンク不要）
9. **`.obsidian/` は触らない**（設定変更を依頼された場合を除く）

## タスク管理

ユーザー向けの説明は `99_System/タスク管理ガイド.md`。ユーザーは `00_Inbox/` に入れるだけで、振り分けと進捗の記録はAIが担当する。

### タスクノート（`05_Tasks/`、テンプレート `99_System/Templates/Task.md`）
- ファイル名は「次の具体的な行動」にする（例: `〇〇の見積もりを依頼する.md`）
- プロパティ:
  - `status`: `todo`（未着手）| `doing`（進行中）| `waiting`（待ち）| `someday`（いつか）| `done`（完了）
  - `today`: 今日やるなら `true`。**同時に3つまで**
  - `priority`: `高` | `中` | `低`
  - `due`: `YYYY-MM-DD`（なければ空）
  - `project`: 関連プロジェクトへのリンク（例: `"[[10_Projects/〇〇/_index]]"`）
- プロジェクト内のタスクも `05_Tasks/` に置き、`project` でリンクする。プロジェクトの `_index.md` からもリンクを張る

### Inbox整理（「Inbox整理して」）
1. `00_Inbox/` 内の全ノートと、`00_Inbox/Inbox.md` の箇条書きを1件ずつ判断する
2. 上記「振り分けの判断基準」で行き先を決める。複数手順でゴールがあるものはプロジェクト＋最初のタスクを作る
3. 書かれた情報から `due` / `priority` / `status` を設定する。人の返事待ち → `waiting`、期限も急ぎもない → `someday`、それ以外 → `todo`
4. 振り分け済みの元メモ: 個別ノートは移動または `90_Archive/` へ。`Inbox.md` の箇条書きは処理したものを消し、行き先は報告とAIログに残す
5. 判断できないものは Inbox に残し、ユーザーに質問する
6. 最後に「どれを・どこへ・どの状態で」振り分けたかを一覧で報告する

### 進捗の更新
- ユーザーが「〇〇終わった」「〇〇は△△待ち」などと言ったら、該当タスクの `status` と `updated` を変え、`## 進捗ログ` に `- YYYY-MM-DD 内容` を追記する
- 「今日やるを提案して」→ 期限・優先度・進行中を見て最大3つ提案し、了承されたら `today: true` を付ける（前日分の `today` は外す）
- 「週次レビューして」→ Inbox整理、`waiting` の催促確認、期限切れ・2週間以上更新のないタスクの洗い出し、`done` から1週間以上経ったタスクを `90_Archive/` へ移動、を行い報告する

### 使い方の指摘
ユーザーの使い方がルールに合っていないときは、黙って直さずにその都度指摘し、正しいやり方を提案する（ユーザーの要望）。
例: `today: true` が4つ以上ある／タスク名が曖昧で次の行動が分からない／定義外の `status` 値を使っている／タスクが実はプロジェクト規模／frontmatter のないノートを Inbox 以外に置いている
